!echo "`e(cmdline)'"|pbcopy

If you know you know.

So if you're like me, and you do most of your estimation in Stata on a Mac (for
the time being), and you script tables using loops rather than writing out each
regression individually,[^merp] then you've probably wanted to magically copy
the command that produced one of your estimates to the paste buffer (that's the
name of the place where text goes after you copy it before you paste it). Let's
say you've run ten models and you want to work on the 5th. 

First, `estimates restore est5` activates the 5th stored estimate (assuming you
saved the estimates with `eststo`, otherwise you can just replace `est5` with
whatever it was you called the model you are interested in).

Second, estimation commands (`eclass`) in Stata save the command that was
actually passed, after expanding any macros and wildcards, in `e(cmdline)`.
Which is nice, but I don't really want to copy and paste from the results
window, I just want it in the clipboard so that I can paste it wherever I want.
So here's what we do:

```Stata
!echo "`e(cmdline)'"|pbcopy
```

Let's break that down. The `!` tells Stata to "shell out" to the operating
system, kinda like launching a terminal window and running the command there. So
the rest of the line is going to be bash commands with one super power: we can
use Stata macros... in particular the ones left behind by the last estimation
command, or in our case the estimation command that we just restored. 

`echo` is bash's version of Python's `print()` or Stata's `display`, in our case
we are just using it to fire off the string produced by evaluating the Stata
macro `e(cmdline)` to bash for further processing. 

In bash like most unix shells command shoot text off into space and if nothing
is there to process it it just gets printed into the console. The pipe operator
`|` acts like... well a pipe. We are just sticking it onto `echo` to catch that
string and send it along to `pbcopy`. 

Let's take a moment to appreciate the glory of `pbcopy`. This is a MacOS command
that takes whatever text you pipe into it and shoots it into the paste buffer.
__That is a super useful thing to do with a pipe!!!__ In this case it means that
we can catch `e(cmdline)` in the paste buffer and then paste it wherever I want.

One of the cool things about learning a little bit about how computers work is
that you start to develop a sense of the sort of things that might work if you
think to ask. This is the wizard of oz problem. Dorthy didn't know what her
shoes could do so she never thought to ask. Seems relevant to life in current
year.

[^merp]: In most cases I think that this is a best practice. It can be more
    complicated initially, but it helps update tables with fewer edits and, I
think, fewer opportunities for errors. For example, if a referee asks for an
additional control variable, I usually only have to make one change rather than
one change for each regression.
